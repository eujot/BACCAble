# CAN knowledge baseline: recordings from September 26–28, 2026

This review combines the earlier recordings with three new sessions. The
[reproducible JSON ledger](20260928-session-review.json) preserves frame
inventories, original events, capture health, signal statistics, time-window
comparisons, IPC sequences, button holds and exploratory bit steps. Input
fingerprints include SQLite, committed WAL, manifest, summary and raw streams.
All source recordings were read without editing their contents.

The current firmware source snapshot is `c550e1619856c60ba64761c48f1bbe6011ebed45`.
That identifies the code used to interpret frames, **not the firmware installed
during every recording**: those versions are not established by the manifests.
The scope is the owner's Giulia recordings; engine, model year and wider vehicle
applicability remain unconfirmed.

## Existing interpretations supported or qualified by new data

**Right indicator:** all four manual ON/OFF events in `204100Z` agree with
BH `0x46C`, byte 6 bits 2–1: `1=right`, `0=center`. Earlier `182645Z` also
supports `2=left`. `181818Z` remains a conflicting recording: ON markers have
opposite-side raw values and two left cycles use a right-OFF label. Original
labels are retained. A request/position field is distinct from the blinking
lamp bits in `0x354` and `0x73E`.

**Driver door:** C1 `0x4B1`, byte 0 bit 0, follows all four new open/close
markers. Together with four matching transitions in `182645Z`, this supports
the historical comment across two sessions. Some older windows contain no
matching transition, so the evidence is not upgraded to universal validation.
Other door, defrost and compressor comments remain independently unvalidated.

**Reverse:** near event 10 in `204100Z`, C2 `0x0FC` byte 3 bits 3–2 changes
to `1`, and BH `0x3E8` byte 3 low nibble changes to `14`. The observed host
transitions precede the marker by about 1.19 s and 0.95 s respectively. These
are the two interpretations already consumed by the parking feature. C1
`0x2EF` does not supply a matching reverse-code transition in that window;
its gear enumeration must not be substituted for the BH gear report.
BH reaches park code `13` at 155.278 s, while the park marker is at 165.531 s.
The fixed four-second window misses this real earlier change: lack of a
window match is not a decoder refutation.

**Ignition:** C1 `0x1EF` low nibble of byte 0 returns to RUN code `8` before
both ignition-ON markers in `204607Z`, by about 0.45 s and 0.39 s. Other raw
codes `2` and `10` occur too; they are not assigned new ignition names here.
The engine stop/start markers also match known RPM threshold transitions.
The `start_stop_restarted` marker in `204100Z` has no matching RPM transition;
that recording stays around idle RPM. Do not use that marker as proof of a
Start/Stop cycle.

**Brakes:** C2 `0x1F5` byte 4 remains a raw pressure report; its source threshold
16 matches 7 of 12 new generic brake markers in the fixed window. Previously
it matched 9 of 10 markers in two earlier recordings. Generic “brake” does not
specify pedal, EPB button, motor movement or completed parking-brake state.
No pressure unit is calibrated. C1/C2 `0x384` byte 3 bit 3 follows explicit
parking-brake ON/OFF markers in `204607Z`, about 0.82–0.93 s after marking;
it also changes near earlier generic brake markers. The park-brake comment is
plausible but still needs isolated pedal/EPB trials.

**SOC:** native IBS C1 `0x41A` byte 1 bits 6–0 gives 84% in all three new
recordings, compared with 77–79% in the older recordings. ECM SOC DID `0x19BD`
was positively decoded in older captures; BCM DID `0x1005` was not. The new
captures contain neither of those positive replies. Missing diagnostic replies
do not mean that the native IBS value disappeared. Raw values above 100 in
the seven-bit field are not silently declared a documented OEM sentinel.

## New exterior-light candidates

Events 10/11 in `204607Z` are a useful ON/OFF pair. Existing comments agree:
BH `0x354` byte 3 bit 6 and C1/C2 `0x384` byte 3 bit 7 change around the markers.
The following additional fields move with that pair:

| Candidate | ON host time | OFF host time | Observation |
| --- | --- | --- | --- |
| BH `0x46C`, byte 5 bit 1 | 265.647627 s | 308.721234 s | `0 → 1 → 0` |
| C1 `0x545`, byte 4 bit 7 | 265.671007 s | 308.878850 s | `0 → 1 → 0` |
| C2 `0x73E`, byte 3 bit 6 | See bit-step ledger | See bit-step ledger | Stable before/after step at both events |

Raw BH examples are `00 90 63 AC D4 0E 00 00` when ON and
`00 90 63 AC D4 0C 00 00` when OFF. In byte 5, `0E XOR 0C = 02` isolates
bit 1. C1 examples are `00 1D 8C 83 80 04 40 00` and
`00 1D 4C 83 00 04 40 00`: byte 4 bit 7 changes, and byte 2 changes too.
Brightness byte 5 remains `04` in these examples, so the new byte-4 bit is
not established as an intensity level.

One ON/OFF pair cannot distinguish low-beam activation, ambient illumination,
parking lights, selector mode or related IPC state. These claims stay in
[hypotheses.json](../../baccable_lab/knowledge/hypotheses.json), with next tests;
no new actuator behavior or executable lamp decoder was added.

## Windows and false correlations

`204100Z` contains `window_open`, `okno otwarte kierowcy` and two
`okno kierwocy zmkniete` events. Event 26 also notes passenger-window opening.
The first marker does not identify a door; the later marker/note combines
controls. No window frame is confirmed. The exploratory screen finds changes
in several unrelated IDs, including BH `0x2F0`, `0x3E2`, `0x46A` and C1
`0x15A`, `0x341`, `0x426`. They are search leads, not window decoders.

Across all sessions the simple bit-step screen returns **2,950 candidates**.
That large number is itself a warning about multiple comparisons. Bits in
`0x4AE` repeatedly change near different kinds of markers, which weakens an
exclusive window/light/parking interpretation. They must be checked against
long baseline behavior and unrelated actions. The same screen misses the
known delayed parking-brake bit because its mixed post-action window does
not reach 95% occupancy. Raw sequence inspection must accompany automatic
rankings; do not name all candidates or reject all misses.

## IPC and media

New `203436Z` has seven complete BH `0x090` text messages with source context
`0x21`; `204607Z` has ten, also `0x21`, plus `0x01`/`0x0F` controls. `204100Z`
has no `0x090` RX frames. Earlier `182645Z` has three complete `0x21` messages
and `185147Z` has 33 `0x06` messages. These contexts correspond to the owner's
CarPlay and USB observations and current source-test labels. Bluetooth `0x09`
exists in the source-test code but is not independently represented here.

New track markers are at 120.454, 134.161 and 140.650 s. The nearest reconstructed
transfer starts are respectively +2.635, -0.195 and -0.445 s from those markers.
That variable delay requires a wider window than a fixed “frame at marker time”
rule. All reconstructed transfers in these recordings have complete ordered
fragments; this does not prove the screen displayed them or retained menu content.

In `185147Z`, all 13 long select/back holds have zero overlapping factory-text
RX frames while BH continues receiving other traffic. The 26 saved hold markers
are derived from CAN and are not independent screen observations. Previous
text can persist during silence; missing BACCAble TX, lease expiry and prior
source/ownership effects cannot be distinguished from RX alone. Across the
full baseline, 76,595 C1 `0x2FA` frames pass CRC-8/SAE-J1850, with no checksum
failure among parsed three-byte samples. This validates the checksum calculation,
not whether every menu action was accepted or rendered.

## Next discriminating recording

A stationary session can resolve several gaps without mixing controls:

1. Driver window down/up three times, then passenger window separately.
   Mark switch press/release and completed open/closed states with door names.
2. Keep lamps steady while changing brightness. Separately mark parking lights,
   manual low beam, AUTO selection without illumination, and actual illumination.
   Repeat each ON/OFF pair; keep other controls fixed.
3. Pedal-only brake cycles with EPB unchanged, then marked EPB operation with
   pedal pressure held steady. Mark button operation and completed state separately.
4. For IPC, mark source selection, track change, menu request, visible menu,
   overwrite and recovery separately. Include long quiet periods after overwrite;
   obtain screen observations and firmware TX diagnostics to distinguish ownership
   and missing refresh from continued radio traffic.

Reuse [the dictionary](../CAN_DICTIONARY.md) to annotate the next recording and
follow [the agent workflow](../SESSION_ANALYSIS.md). Keep new evidence, negative
controls and contradictions alongside the original claims rather than replacing
old meanings whenever a fresh session disagrees.
